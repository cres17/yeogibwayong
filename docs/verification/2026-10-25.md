# Android 사용 가능성 보완 검증 — 2026-10-25

## 변경 범위

- root 라이브러리의 `overlayMain`과 실제 Android 오버레이 서비스 클래스 연결. 수신 경쟁 시 DB에서 대표 펫을 읽고 30초 watchdog으로 닫음.
- UCrop Activity, 예약 알림 receiver, launcher 앱 조회 queries, 인터넷 권한 선언 보완.
- 중단된 device_apps 의존성을 제거하고 백그라운드 executor의 Kotlin 앱 목록 조회로 교체.
- 명시적 권한·사용자 감시 설정 확인, 서비스 시작 실패 시 설정 되돌림, 영구 팝업 간격 기록.
- UsageEvents로 일자·화면 잠금·현재 앱을 반영하고 DB 하루 스냅샷을 원자적으로 교체.
- 타이머 실행 상태 저장, 재시작 복구, 완료 중복 방지, 저장 실패 재시도. SQLite v1→v2 마이그레이션.
- 권한 안내 재확인, 온보딩 건너뛰기 유지와 스크롤, 사진 작업 오류 안내, 대표 펫 삭제 시 대체 선택.
- 홈 타이머 진입점, 팝업 미리보기, 광고 기본 비활성화, placeholder 개인정보 링크 제거.

## 로컬 검증

환경: macOS arm64, Flutter 3.44.6 / Dart 3.12.2, Temurin JDK 21, Android SDK 36.

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

이 호스트의 SDK/Java 자동 탐색 설정이 잘못되어 APK 빌드 시 다음 경로를 지정했다.

```sh
ANDROID_HOME=/opt/homebrew/share/android-commandlinetools \
JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home \
flutter build apk --debug
```

- 단위/위젯 테스트: 33개 통과 (타이머 9, 이벤트 집계 7, 권한 4, 사용량 상태 4, 위젯 5, 오버레이 응답/픽셀 배율 4).
- 위젯 테스트: 375×667, 667×375, 텍스트 배율 2에서 타이머 시작/정지/재개, 권한 허용 후 즉시 갱신.

## 남은 실기기 확인

| 흐름 | 확인할 동작 |
|---|---|
| 사진 | 갤러리 선택 → UCrop → 이름 → 대표 사진 저장/교체/삭제 |
| 감시 | 5분 제한 앱 사용 → 전면 앱에만 팝업 → 10분 내 중복 방지 |
| 권한 | 감시 도중 사용 기록/오버레이 권한 회수 → 앱에서 재안내 |
| 백그라운드 | 화면 잠금, 앱 프로세스 종료, 재부팅, 삼성·샤오미 절전 |
| 타이머 | 5분 시작 → 앱 종료 → 알림/복구. 알림 시점은 inexact 정책상 지연 가능 |
| 마이그레이션 | 기존 설치의 v1 DB를 보존하면서 v2로 업그레이드 |

자동 테스트의 가짜 시간·가짜 저장소 결과는 물리 기기의 백그라운드 동작 증거와 구분한다. 서비스 타입 `specialUse`는 기능에 맞춰 명시했지만 Play Store 승인을 의미하지 않는다. 운영 서명/광고 설정/정책 페이지 배포는 이번 변경에 포함하지 않는다.

## Android 35 통합 검사 첫 실행 및 보완

[실행 40169716720](https://github.com/cres17/yeogibwayong/actions/runs/40169716720): 원격 분석·29개 테스트·debug 및 세 ABI 최적화 APK 빌드는 통과했다. 에뮬레이터 부팅 후 통합 검사는 홈 진입 대기 단계에서 실패했다. 고정 시간 대기를 화면 준비 조건 대기로 교체했다. 또한 `flutter test`가 생성하는 별도 bootstrap root에서는 오버레이 플러그인의 root entrypoint를 찾지 못하는 로그가 확인되어, 명시적 테스트 root를 실행하는 `flutter drive`로 통합 실행 방식을 변경했다. 실제 앱의 기본 진입점은 `lib/main.dart`에 유지한다.

실패한 통합 검사도 최적화 앱의 별도 시작 검사를 이어 실행하고, 앱 PID의 로그로 판정하도록 개선했다. 플랫폼 전체의 Google 서비스 오류는 앱 실패 판정에 섞지 않는다.


[실행 40170846384](https://github.com/cres17/yeogibwayong/actions/runs/40170846384)에서는 `flutter drive`로 앱 시작/홈 진입까지 진행됐으며, 실제 Android 폰트로 펫 영역을 그릴 때 15px의 세로 overflow가 검출됐다. 펫 영역을 고정 높이 대신 최소 높이와 내용 기반 Column으로 변경했다. 별도 최적화 앱 시작 검사에서는 앱 프로세스가 유지됐고 startup/entrypoint 오류가 없었으며 온보딩 화면 캡처가 남았다. 통합 검사의 나머지 네이티브 항목은 후속 실행에서 다시 확인한다.


## 팝업 메시지 대기 및 배율 보완

[실행 40178028179](https://github.com/cres17/yeogibwayong/actions/runs/40178028179)의 부분 로그는 앱 시작·사용 권한 확인·팝업 서비스 시작까지 진행됐으며 이후 응답 대기에서 멈춰 진단을 위해 실행을 취소했다. Flutter drive 기본 `start-paused`가 별도 오버레이 엔진에 영향을 줄 수 있어 `--no-start-paused`로 변경했다. 검사 단계별 20초, 테스트 2분, 드라이버 3분, CLI 4분의 대기 제한과 실패 시 캡처를 추가했다.

앱에서도 플랫폼 메시지 응답은 2초로 제한하고, 이미 닫힌 팝업의 close 호출이 응답 없이 대기하지 않도록 보완했다. 오버레이 재개 시 대표 사진/표시 시간을 다시 불러온다. Android 플러그인에 전달하는 크기는 물리 픽셀로 변환하여 고밀도 화면에서 Flutter 카드가 잘리지 않게 했다. 이 네 가지 경우를 포함한 33개 테스트와 정적 분석이 통과했다.

## 네이티브 검사 완료 및 최적화 앱 복원 오류

[실행 40180145433](https://github.com/cres17/yeogibwayong/actions/runs/40180145433), 커밋 `0c87fb7a4e6d5288de5eacd4b9f82a4d1dd4cec6`: Android 35 앱 logcat에서 설치 앱 조회, SQLite 타이머 시작/일시정지/재개/취소, 팝업 표시/닫기가 모두 완료되고 `All tests passed!`가 기록됐다. 홈 화면 캡처도 확인했다. 다만 호스트 드라이버가 VM 서비스 연결에서 시간 초과되어 Actions 실행 자체는 실패다. 후속 실행은 DDS를 끄고 직접 VM에 연결한다.

같은 실행의 최적화 APK 교체 설치에서 예약 알림 boot receiver가 Gson `Missing type parameter`로 종료됐다. WorkManager가 다른 PID를 시작해 프로세스 존재만 확인하는 기존 검사로는 놓칠 수 있었다. flutter_local_notifications 18.0.1의 공식 예제에 따라 Gson TypeToken/Signature 규칙을 추가했다. 이제 교체 설치부터 crash buffer를 수집하고, MainActivity가 실제 resumed 상태인지도 확인한다. 이 수정의 최적화 실행 결과는 후속 CI와 PR에 기록한다.

근거: [알림 플러그인 v18.0.1 릴리스 설정](https://pub.dev/packages/flutter_local_notifications/versions/18.0.1), [Gson R8 설정](https://github.com/google/gson/blob/main/Troubleshooting.md).
